# Урок 3.4 — Соединение нескольких таблиц: заказы, позиции и справочники

## Цель урока

- прочитать несколько таблиц Olist в отдельные DataFrame’ы;
- научиться соединять таблицы по ключам через: DataFrame API (`join`) и Spark SQL (`JOIN`);
- научиться соединять разбивать сложный join на понятные шаги, а не собирать один громоздкий запрос.

## Источники данных

Используем несколько таблиц Olist:

- `olist_orders_dataset.csv` — заказы
- `olist_order_items_dataset.csv` — позиции заказа
- `olist_products_dataset.csv` — товары
- `olist_customers_dataset.csv` — клиенты

Внутри контейнера Spark все эти файлы лежат в общей папке:

- `/data/olist_orders_dataset.csv`

- `/data/olist_products_dataset.csv`
- `/data/olist_customers_dataset.csv`

## Почему grain здесь критичен

У каждой таблицы есть **гранулярность**, или grain — чёткий ответ на вопрос «что означает одна строка».

В этом уроке нас интересуют три варианта:

- заказы: одна строка = один заказ;
- позиции заказа: одна строка = одна позиция в заказе;
- обогащённые позиции: одна строка = одна позиция заказа + атрибуты из справочников.

Если забыть про grain и сделать join «на глаз», легко получить дубли, завышенные суммы и некорректные агрегаты.

Поэтому здесь важно:

- сначала формулировать, какой grain нужен;
- только потом строить join и проверять счётчики.

## Структура урока

В ноутбуке шаги разложены последовательно.

1. **Импорты и SparkSession**  
   Лёгкая проверка, что `spark` доступен в стенде `spark_01`.

2. **Определение путей**  
    Ещё раз фиксируем, что читаем из `/data` и пишем в `/workspace/samples/lesson03_04`.

3. **Чтение таблиц Olist**  
   Загружаем четыре таблицы в отдельные DataFrame’ы и коротко смотрим на:
   - схему;
   - пример строк;
   - количество записей.

4. **Grain и проверка счётчиков до join**  
   Для каждой таблицы считаем:
   - общее количество строк;
   - количество уникальных `order_id` / `customer_id`.  
   Это отправная точка до соединений.

5. **Соединение `order_items` и `orders` (DataFrame API)**  
   Собираем учебную витрину позиций заказа с датой и статусом. После join снова проверяем счётчики.

6. **Добавление атрибутов товаров и клиентов**  
   На том же grain (`order_id + order_item_id`) добавляем из справочников:
   - категорию товара;
   - город клиента.  
   Join делаем пошагово, с проверкой после каждого соединения.

7. **Тот же результат через Spark SQL**  
   Регистрируем DataFrame’ы как временные представления и пишем эквивалентный SQL‑запрос. 
   Получаем тот же результат и сравниваем счётчики.

8. **Запись итоговой витрины в Parquet**  
   Пишем итоговую таблицу учебных позиций заказа в директорию `/workspace/samples/lesson03_04/order_items_enriched_parquet`, 
   затем читаем её обратно и проверяем `count()`.
